# Локальное место, регион и timezone

Место (`Place`) содержит независимые координаты, устойчивый ID, название, способ выбора
(`gps`, `city`, `official`), регион, доказательство покрытия и timezone с происхождением.
Ручной выбор города не меняет профиль расчёта. Выбор таблицы хранится отдельно от места:
для GPS она не заменяет координаты и не задаёт название. ID GPS сохраняется при refinement;
город имеет GeoNames ID, официальный пункт — ID населённого пункта.

## Покрытие и точность

Поддерживаемая географическая территория — только Республика Татарстан, `RU-TA`.
Базовый precache содержит `data/tatarstan-boundary.json`: 72 241 байт, 3 651 вершина.
Мировой polygon-набор не поставляется. Отдельные пакеты GeoNames могут отсутствовать;
это влияет только на название-ориентир, а не регион, timezone или готовность расчёта.
GPS lookup использует существующий nearest-city API с `localOnly: true`, радиусом 25 км
и не загружает географически выбранные пакеты из сети. Общий индекс городов имеет постоянный URL.

Источник границ: OpenStreetMap / Wambacher через geoBoundaries gbOpen,
`RUS-ADM1-28173009`, версия Git `9469f09`, год территории 2017, сборка 12.12.2023.
[Метаданные](https://www.geoboundaries.org/api/current/gbOpen/RUS/ADM1/).
Снимок не является кадастровым или геодезическим доказательством. Проверка покрытия
означает соответствие этой локальной модели; гарантированную точность источник не заявляет.

Из полного GeoJSON извлечён только feature `shapeISO=RU-TA`. Исходная выборка без изменения
координат сохранена в `scripts/geography/tatarstan-source.geojson`; SHA-256, закреплённый URL
и способ извлечения — в `provenance.json`. Подготовка не требует сети:

```sh
npm run data:build:geography
npm run data:check:geography
npm test -- scripts/buildLocalGeography.test.ts src/domain/localGeography.test.ts
```

Скрипт применяет Douglas–Peucker с допуском 100 м, сохраняет острова/отверстия, округляет
координаты до 5 знаков и ограничивает размер 80 КиБ. Runtime проверяет формат пакета.
Точки сравниваются со всеми кольцами MultiPolygon: ray casting для принадлежности,
расстояние до сегментов в локальной метрической проекции. Это узкая модель Татарстана,
не универсальная геометрия для полюсов или линии перемены дат.

Политика однозначна: внутри контура и дальше `2000 м + accuracy` от любого кольца —
`inside`; снаружи и дальше этого расстояния — `outside`; на линии/в этой полосе,
при неизвестной точности — `uncertain`; отсутствующий/невалидный пакет — `unavailable`.
Два километра — консервативный запас приложения для неточности и возраста данных,
а не математически доказанная погрешность OSM. Название и доступность сети не участвуют.
GeoNames admin1 `RU.73` допустим как доказательство для явно выбранного города, но не GPS.

Для `inside` выбирается ближайший из опубликованных пунктов ДУМ РТ по haversine,
без произвольного радиуса: это сохраняет прежнее правило в пределах покрытия.
Равные расстояния разрешаются порядком опубликованного списка. UI прямо называет
пункт таблицы. Таблица не объявляется опубликованной для любой точки внутри региона.
Для `uncertain`/`outside`/`unavailable` используется автономный расчёт по реальной точке.
Тесты включают Казань, Москву, Вятские Поляны (в bounding box, вне республики),
Октябрьский и Бавлы по сторонам восточной границы, вершины исходных колец, отверстия
и неопределённую точность GPS.

## Timezone

Город использует проверенный IANA ID из каталога. GPS внутри подтверждённой модели
использует `Europe/Moscow`; за пределами этого покрытия, включая пограничную полосу,
использует timezone устройства с видимым указанием fallback. Timezone ближайшего города
не переносится на GPS. Привязка Татарстана: московская часовая зона,
[статья 5 закона об исчислении времени](https://base.garant.ru/12186461/5633a92d35b966c2ba2f1e859e7bdd69/),
[IANA tzdb](https://www.iana.org/time-zones). Данные нуждаются в пересмотре при изменении границ или часовых зон.

В диалоге места можно ввести любой поддерживаемый браузером IANA ID и вернуть автоматический.
Override хранится как `{ id, source: 'user' }`, автоматическая зона — отдельно.
Повторный GPS для уже выбранного GPS-места сохраняет override; новый ручной город/пункт
или переход от ручного города к GPS сбрасывает его. Изменение timezone отменяет применение
ожидающих результатов GPS/lookup текущей операции. DST вычисляет `Intl`, offsets не хранятся.

Таблицы ДУМ РТ всегда показывают исходные часы и календарную дату в `Europe/Moscow`.
Пользовательская timezone сохраняется у места, но не переинтерпретирует опубликованные часы.
В UI это объясняется. Моменты событий/countdown по-прежнему строятся из timezone поставщика;
автономный расчёт использует timezone места и реальные координаты.

## GPS, актуальность и гонки

Сохранённое место передаётся UI сразу после локального чтения, до проверки manifest по сети.
Ручной/default выбор никогда сам не запускает GPS. Автоматический выбор моложе 30 минут
не запрашивает даже permission; более старый или с будущим timestamp обновляется только
при уже выданном разрешении. При отказе сохранённое место остаётся доступным.

Используются два одноразовых `getCurrentPosition`: coarse (10 с, maximumAge 10 минут)
и precise (30 с, без кеша), запускаемые параллельно. Первый валидный fix даёт расписание,
не ожидая precise или названия. Проверка небольшого геопакета ограничена 1,5 с;
при недоступности действует явный fallback. Непрерывного watchPosition нет.

Refinement принимается при не худшей точности и хотя бы одном условии:
изменилось покрытие/автоматическая timezone; смещение больше `max(100 м, accuracy₁ + accuracy₂)`;
точность улучшилась хотя бы вдвое и минимум на 100 м. Косметическое имя не меняет точку.
Поздний coarse после принятого precise игнорируется. Ошибка precise сохраняет coarse.

Epoch отсекает результаты после нового запроса, ручного выбора, настройки зоны и unmount;
номер fix внутри epoch отсекает старый lookup. Сохранения сериализованы и проверяют epoch
перед началом и после открытия IndexedDB: после медленной записи последним сохраняется актуальный выбор.
`AbortController` не используется для фиктивной отмены `getCurrentPosition`.
Контекст расписания включает настоящую точку, таблицу, дату и применённую timezone;
старые события скрываются уже во время render при смене контекста.

## Миграция и приватность

IndexedDB v7 выполняет последовательную миграцию после v5/v6. Сохраняет прежние координаты,
названия (включая `nameSource: nominatim`), официальный пункт и источник выбора.
Legacy-поля не определяют новые места; происхождение прежней timezone помечается `legacy`.
Если старая официальная запись не содержала GPS-точку, восстановить её нельзя:
сохраняется опубликованный пункт, а автоматический режим сможет обновить GPS при разрешении.

Runtime reverse-geocoder, кнопка онлайн-уточнения, его service-инъекция и разрешение
Nominatim в CSP удалены. Новые координаты не добавляются к URL/body и не журналируются.
Старая runtime-реализация кешировала только название в записи места; отдельного сетевого
кеша Nominatim не было. OSM/ODbL attribution сохраняется для локальной производной базы.
GitHub Pages получает обычные сетевые метаданные статических запросов; служба геолокации
браузера/ОС может иметь собственное сетевое поведение, которым приложение не управляет.
