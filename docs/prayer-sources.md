# Выбор источника и сохранение

## Resolver

`resolvePrayerTimeSource` — чистая функция. Входы: Place, календарная дата либо
момент времени, SourcePreferences, локальные дескрипторы официальных наборов
и список поддерживаемых браузером профилей. Сеть, navigator, геокодер и часы
устройства внутри resolver не используются. Для Date календарный год каждого
официального кандидата проверяется в зоне поставщика; для расчёта используется
зона места. Строковая дата — дата, явно выбранная в календаре.

Порядок: ручной источник → официальное покрытие → региональный расчёт → MWL.
Официальные кандидаты сортируются по числовому priority (меньше — раньше),
затем provider id по кодовым единицам; подтверждённая локальная версия одного
поставщика предшествует ожидаемой загрузке, последний tie-break — revision.
Production registry содержит только ДУМ РТ (priority 10, RU-TA,
Europe/Moscow). Наборы других организаций не придуманы. Расчётные профили
ДУМ РФ и Diyanet никогда не обозначаются как официальные таблицы.

Покрытие ДУМ РТ известно до сети из `dumRtCoverage.json`: метаданные
поставки, годы и опубликованные пункты, **без строк времени**. Оно проверяется
на соответствие исходному набору тестом и обновляется обеими командами
`data:update` / `data:update:prayer-manifest`. Сейчас опубликован 2026 год.
Для подтверждённого Place внутри Татарстана сохраняется правило ближайшего
пункта; ручной пункт таблицы сохраняет свой id. Неизвестный регион, название
города и близость к границе не доказывают покрытие.

Если подтверждённая локальная версия покрывает дату, используется она, даже
при ошибке refresh. Если есть только известное покрытие, результат official
имеет `not-loaded` или `invalid`; сетевой сбой не включает calculated.
Без покрытия года/места automatic разрешает расчёт, а manual official
возвращает `not-covered`, сохраняя ручной выбор. Год таблицы не растягивается.

## Расчётная стратегия

Проверено 7 сентября 2026 года по установленному `adhan 4.4.6` и
[руководству авторов adhan](https://github.com/batoulapps/adhan-js/blob/develop/METHODS.md).
Это явно выбранные defaults приложения, а не утверждение об обязательной
методике для всех общин страны. Регион берётся только из Place; GPS вне
подтверждённой территории с неизвестной страной использует общий fallback.

| Подтверждённый регион | Профиль | Базовый Аср |
| --- | --- | --- |
| Татарстан, без официального покрытия даты | ДУМ РТ, существующие 18°/15° и северное 120/90 | hanafi |
| РФ вне Татарстана (RU) | ДУМ РФ, 16°/15° | hanafi |
| Турция (TR) | Turkey: приближение Diyanet в adhan | standard |
| Пакистан, Бангладеш (PK, BD) | Karachi, 18°/18° | hanafi |
| США, Канада (US, CA) | NorthAmerica / ISNA, 15°/15° | standard |
| Саудовская Аравия (SA) | UmmAlQura при поддержке islamic-umalqura | standard |
| Остальные и неизвестные регионы | MuslimWorldLeague, 18°/17° | standard |

MWL выбран общим переносимым fallback, без локальных поправок Турции или
сезонного календаря Умм аль-Кура. С 11 сентября 2026 года ДУМ РФ выбран
автоматическим профилем для остальных известных мест РФ как правило приложения;
это не утверждение о единой методике всех общин страны. Автоматически
никогда не выбирается профиль, отсутствующий в переданном списке capabilities.
Без явно переданных capabilities Умм аль-Кура не считается поддерживаемым.
Неподдерживаемый manual сохраняется и показывает причину недоступности.

Для всех defaults кроме ДУМ РТ при |широта| > 48° используется 1/7 ночи,
иначе доля по углу; полярный цикл — ближайшая пригодная широта. Это продуктовая
стратегия на основе рекомендаций авторов adhan; существующий ручной nearestDay
и северное правило ДУМ РТ сохраняются. Профиль Умм аль-Кура сохраняет сезонный
интервал Иша 90/120 минут, проверку календаря и расчёт Рамадана по зоне места.
Turkey сохраняет поправки и округление библиотеки. Официальные часы и
календарная дата позднего сухура описаны в [хронологии](prayer-chronology.md).
[Официальные публикации ДУМ РТ](https://dumrt.ru/ru/help-info/prayertime/) служат
источником таблиц; приложение не выводит их из расчётных углов. При итоговой проверке 7 сентября 2026 года страница ответила HTTP 200 и
содержала ссылки на CSV и XLSX 2026 года. Это заменяет прежнее наблюдение HTTP 410;
байты поставляемого набора не обновлялись и новые годы не объявлялись.

## Preferences и миграция v8

Выбор места (`locationChoice.source`) и источника (`sourcePreferences.mode`)
независимы. Новый пользователь получает automatic. Миграция 7 → 8 выполняется
после предыдущих миграций в той же upgrade-транзакции, без удаления старых
настроек, места, override timezone или расписаний.

- Валидные новые preferences сохраняются как есть.
- Без legacy `calculationSettings` старое место сохраняется, источник automatic:
  прежний locationMode выбирался географией и не доказывает ручной источник.
- Наличие валидной записи `calculationSettings` означает прежнее редактирование,
  даже если значения совпадают со старым default. При calculated сохраняется
  manual calculation; при official — manual ДУМ РТ с расчётным draft.
- Это консервативное правило для неоднозначного состояния: не теряются ни
  действующая таблица, ни пользовательские параметры. Невалидные записи не
  применяются, но исходный legacy record не удаляется.

Расчёт хранит `profile` и явные `overrides`, а базовые параметры определяются
профилем. Редактирование расчёта включает manual; смена профиля сохраняет уже
явные overrides. Возврат в automatic одним действием оставляет draft, но он
не влияет на региональный resolver. Повторный ручной выбор расчёта может его
восстановить. Главный экран использует только эффективные параметры.

В расширенной модели поддержаны Аср, северное правило, угол Фаджра 1–30°,
Иша как угол 1–30° **либо** целый интервал 1–240 минут, целые поправки −180…180
минут для каждого calculated-события (включая солнечные отметки). NaN,
Infinity, неизвестные поля/события и одновременные angle/interval отклоняются.
Диапазоны — границы ввода приложения, не религиозные рекомендации.

Custom Иша interval считается от Магриба профиля до пользовательских поправок;
каждая поправка затем независимо сдвигает absolute instant соответствующего
события. Отображаемые часы и дата получаются из нового instant. Углы участвуют
в проверке доступности сумерек; признаки северного/полярного приближения
сохраняются. Официальные таблицы не корректируются. Расчётное окно расширено
до D−4…D+4 для offsets −3…+3 с поправками; выход за пределы даёт явную ошибку.

ScheduleContext содержит реальное место и координаты, дату, timezone, mode,
provider, пункт/покрытие, dataset version/revision либо все эффективные
расчётные параметры. Draft не меняет времена automatic. При смене контекста
старое окно скрывается уже во время render, до запуска нового effect.

## Локальное чтение и обновление

`initialize` читает только IndexedDB и восстанавливает настройки. Проверка
локального набора включает схему, реальные даты/времена, координаты,
уникальность и полный календарный год для каждого опубликованного пункта.
Первый полезный render не ждёт manifest; cold start без meta открывает выбор
места и позволяет рассчитывать подходящие места локально.

Отдельный `refresh`: manifest → bytes → SHA-256 → schema/полнота → атомарная
замена days/meta → уведомление подписчиков. На всё сетевое чтение и digest
задан timeout 8 секунд и AbortController, включая зависшее тело ответа.
Одинаковые пересекающиеся refresh дедуплицируются. Даже транспорт,
игнорирующий abort, не может установить поздний ответ после инвалидирования.

Manifest schema 1 расширен optional `sequence`; новая поставка начинает с 1.
Команды генерации сохраняют номер при тех же байтах и увеличивают при новых.
Hash остаётся идентичностью содержимого, sequence задаёт порядок публикаций.
Установка проверяет исходную revision повторно внутри readwrite-транзакции,
запрещает меньший sequence, другой hash при том же sequence и более ранний
source.updatedAt. Старые manifest без sequence читаются для совместимости,
но не могут заменить уже нумерованную публикацию. Между legacy-публикациями
без sequence порядок ограничен updatedAt и transactional compare-and-swap;
контентный hash сам по себе не задаёт возраст. Старый рабочий набор сохраняется
при timeout, hash/schema error, stale response и откате транзакции.

Repository публикует только согласованный snapshot с meta, dataState,
update.status/reason и временем последней успешной проверки. SourceInfo показывает источник и статус проверки; фоновые технические ошибки на главный экран не выводятся.
При `online`, `pageshow` и ручном повторе запускается revalidation. Между
вкладками дополнительно защищает проверка revision при чтении days/meta;
повтор обновляет метаданные. Локальная подписка не является глобальным state
manager. Manifest и JSON времени исключены из Workbox Cache Storage:
каноническая таблица хранится только в IndexedDB. Auto-update SW сохранён.

## Ошибки записи и сброс

Одна небольшая очередь settings хранит актуальный частичный снимок **всех**
изменённых полей места/источника. Записи последовательны; устаревшая ещё не
начавшаяся операция пропускается. Изменённые поля одного снимка пишутся одной
транзакцией, success возвращается после `transaction.done`. Отклонение Promise
и Result.ok=false дают одинаковое неблокирующее сообщение и «Повторить».
Ошибка старой операции не меняет новый UI/статус; повтор записывает актуальный
снимок, включая прежние несохранённые поля. До commit изменение считается
действующим в памяти, но не подтверждённым как сохранённое.

Очередь предоставляет `drain` и `invalidateAndDrain`; repository —
`invalidateAndDrain` для refresh. Действующий reset останавливает UI/GPS,
инвалидирует операции и дожидается очереди и начавшейся установки, затем одной
транзакцией очищает пользовательские stores и увеличивает поколение. Проверка
поколения защищает от старых вкладок. Unmount отписывает UI и отменяет refresh;
уже запрошенные записи завершаются без обращения к снятому компоненту.
Схема v9, граница удаления, уведомления вкладок и поведение после перезапуска
описаны в [локальных данных](app-data.md).
