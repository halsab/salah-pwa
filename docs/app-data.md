# Настройки и локальные данные

Базовые настройки содержат место, оформление (по умолчанию системное), статус
автоматического или ручного выбора времени и действия с данными. Экспертная форма
доступна по пути «Настройки → Время намаза → Расширенные настройки». Числа
применяются одной валидированной операцией; смена источника явно включает manual.
Возврат в automatic сохраняет экспертный черновик, но не применяет его overrides.

«Настройки → Данные → Сбросить данные приложения» после подтверждения очищает все
записи `settings`, `days` и `meta` базы `salah`, включая неизвестные legacy-ключи.
В схеме v9 отдельный store `control` хранит только безличный счётчик поколения.
Счётчик увеличивается в той же транзакции, что и очистка. Он не содержит места,
времени сброса, координат, истории или других пользовательских сведений.

Перед очисткой текущая вкладка инвалидирует GPS/lookup, очередь сохранений и
refresh, дожидаясь уже начавшихся записей. Репозиторий фиксирует поколение при
инициализации; сохранения настроек и установка таблицы проверяют его внутри своей
транзакции. Поэтому даже ещё не уведомлённая вкладка не может вернуть старую запись.
После успешной очистки BroadcastChannel уведомляет другие экземпляры, а проверка
поколения при focus/pageshow/visibilitychange охватывает возвращающиеся вкладки.
Перезагрузка освобождает React state и ссылки на данные. При новом запуске после
сброса нет выбранного места и фонового запроса GPS или таблиц до выбора места.

Очистка stores не требует deleteDatabase и не блокируется открытыми соединениями.
Ошибка транзакции отменяет очистку целиком и остаётся видимой с повтором.
Запросы очистки ожидаются последовательно внутри одной транзакции: синхронный
отказ очередного запроса не оставляет предыдущий Promise без обработчика; отмена
подтверждения не меняет данные. После сброса пользователь может явно выбрать место
и начать новую сессию, включая автономный расчёт.

Граница очистки исключает публичную базу `salah-city-catalog`, precache оболочки,
service worker, шрифты, справочники и статические пояснения. Эти ресурсы не содержат
пользовательских записей. Разрешение браузера на геопозицию приложение не отзывает.

Статические пояснения находятся в template-элементах HTML-оболочки и входят в её
precache. Компоненты клонируют только эти доверенные узлы; динамические факты и
параметры расписания остаются в React. Это сохраняет офлайн-доступность без
дополнительного запроса и укладывает интерфейс в прежние бюджеты JavaScript.

## Инвентаризация хранения и сетевых потоков

- `salah.settings`: текущее Place (координаты, название, источник выбора,
  регион/покрытие, timezone и override; для GPS — точность и timestamp),
  `sourcePreferences` с manual draft, `appearance`. Старые записи параметров
  могут сохраняться миграцией ради совместимости. Истории поисков и перемещений нет.
- `salah.days` / `meta`: только проверенный официальный dataset и его идентичность.
  Рассчитанные окна, дата просмотра, текст поиска и текущая операция GPS живут
  в памяти; они не являются журналом действий. Время последней проверки таблицы
  (`checkedAt`) тоже хранится только в памяти repository.
- `salah-city-catalog`: публичные пакеты, текущий и предыдущий индексы. Набор
  скачанных пакетов косвенно связан с выполненными поисками; reset его сохраняет.
- Workbox Cache Storage: оболочка, шрифты, QR, политика, обзор, геограница и её
  атрибуция. Ни официальный dataset, ни runtime-пакеты городов сюда не записываются.
- `sessionStorage['salah:service-worker-reload-at']`: время последней автоматической
  перезагрузки; guard действует 10 секунд, запись остаётся на время сеанса вкладки.
  Reset её не удаляет. `salah.control.generation` также сохраняется без срока до
  очистки сайта; он нужен, чтобы старые вкладки не возвращали удалённые данные.
- Приложение не вызывает `persist()`, не обещает бессрочное хранение и не использует
  cookies/localStorage, аккаунты, удалённые резервные копии или идентификатор пользователя.
  Браузер может вытеснить данные или удалить их в приватном режиме.

Все runtime-загрузки идут с origin установки под `/salah-pwa/`:

| Действие | Запрашиваемые данные | Что не передаётся приложением |
| --- | --- | --- |
| Первый запуск | HTML, JS/CSS, локальные шрифты/изображения, SW, manifest, базовые публичные данные; manifest таблицы и её JSON для первоначальной установки | GPS, настройки |
| Повторный запуск | Оболочка из precache, проверка SW и manifest таблицы; при совпадении идентичности JSON таблицы не скачивается | Сохранённое место и параметры |
| GPS / разрешённый устаревший GPS | Постоянный URL геограницы и общий индекс; поиск ориентира только в уже сохранённых пакетах | Координаты, точность и timestamp |
| Поиск города | Индекс и подходящие `cities/VERSION/COUNTRY-N.json` | Строка поиска; состав пакетов виден хостингу |
| Выбор города / настройки | Сохранение локальной записи; готовность таблицы зависит от фонового refresh | Выбранный ID/настройки |
| Проверка таблицы | `prayer-times-manifest.json`; при изменении — `prayer-times-current.json` | Место/дата просмотра: скачивается весь публичный набор |
| Поделиться | Статический `share-qr.svg`, копирование текущего URL в Clipboard API | Приложение не добавляет место/настройки к URL и не отправляет сообщение |
| Reset | Локальная транзакция, уведомление вкладок и reload оболочки; таблицы/GPS не запускаются до нового выбора | Удалённые записи |

Workbox может добавлять `__WB_REVISION__` для публичного precache; это идентичность
артефакта, а не пользователя. Стандартные IP, заголовки, путь и время HTTP-запроса
видны статическому хостингу. Состав пакетов не равнозначен точной GPS-позиции,
но абсолютное обещание «никакие данные не передаются» неверно.

Публичное размещение — GitHub Pages. Его документация прямо описывает
[сохранение IP посетителей](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection);
[политика GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement)
описывает обработку сетевых метаданных. Сверено 7 сентября 2026 года.
Это отдельная обработка хостинга, не аналитика Salah. Работа сетевого провайдера
Geolocation API браузера/ОС и переходы пользователя на внешние ссылки находятся
за пределами запросов приложения. Исходники ДУМ РТ/GeoNames/geoBoundaries
скачиваются при подготовке данных; они не являются runtime-получателями GPS.
