# Каталог городов: schema 4

## Данные и поиск

Сохранены все 69 037 GeoNames ID, координаты, население, страна, `admin1Code` и
IANA timezone исходного набора. `admin1Name` импортируется из GeoNames; источник,
снимки и CC BY 4.0 указаны в `THIRD_PARTY_NOTICES.md`. При отсутствии имени показываем
«регион CODE», при отсутствии самого региона — «регион не указан». Страна видна
в каждой строке. Совпадающие название, регион и страна дополнительно различаются
GeoNames ID. Два Кирова: ID 548408 (Кировская Область, Europe/Kirov) и ID 548410
(Калужская Область, Europe/Moscow).

Tuple хранит поля:
`[id, name, normalizedNames[], countryCode, admin1Code, lat, lon, population, timeZone, admin1Name, normalizedContext]`.
Первый поисковый ключ — основное отображаемое имя; остальные — самостоятельные
действующие русские имена, имя GeoNames и ASCII-вариант. NFD, удаление диакритики,
нижний регистр и сведение пробелов применяются при генерации и к запросу.
Контекст страны/региона хранится отдельно. Поддерживаются подстроки и несколько
слов, включая запросы вроде «Киров Калужская», `Istanbul`, `New York`, «Йошкар Ола».

Ranking: точное основное имя → начало основного имени → точное альтернативное →
начало альтернативного → подстрока имени → совпадение с контекстом. Затем население
по убыванию и GeoNames ID по возрастанию. Ограничение 60 применяется **после**
общего ранжирования. UI сохраняет этот порядок между странами.

## Пакеты и локальный контракт

`/salah-pwa/data/cities/index.json` содержит версию, собственную контрольную сумму,
657 городов (до трёх крупнейших в каждой стране), описания 399 пакетов с размером и SHA-256,
Bloom-фильтры триграмм и занятые пространственные ячейки 2°.
`/salah-pwa/data/cities/VERSION/COUNTRY-N.json` содержит не более 300 городов.
Крупные страны делятся после сортировки по широте, долготе, ID. Порог генератора —
110 KiB полезной нагрузки; внешний бюджет каждого JSON — 128 KiB.

`CityCatalogService.load()` возвращает обзор; `search()` — города и статус:

- `complete`: все подходящие пакеты проверены, пустой ответ означает отсутствие
  совпадений в этой версии и выборке GeoNames.
- `needs-download`: часть пакетов отсутствует/недоступна; доступные города остаются
  видимыми, UI предлагает подключиться и повторить поиск тем же запросом.
- `refine`: нет слова из трёх букв либо кандидатов больше 32. Показывается обзор и
  просьба уточнить название/регион, никакие пакеты для такого запроса не скачиваются.

Bloom-фильтры могут направить к лишнему пакету, но не исключают подходящий. Это
намеренный обмен нескольких небольших запросов на компактность индекса. Поиск,
декодирование индекса, проверка и разбор JSON выполняются в существующем Worker.
Операции сериализованы, внутри операции — две загрузки одновременно. Новое поисковое
сообщение отменяет дальнейшие загрузки старого запроса после текущей пары. Поздний
ответ игнорируется UI. В памяти остаются четыре пакета LRU; рабочая выборка одной
операции ограничена 32 пакетами, затем результат — 60 городами. Сбой Worker
завершает ожидающие promises; следующий запрос создаёт новый Worker. Таймаут
одного fetch — 15 секунд, ожидания Worker — 120 секунд.

`findNearest(lat, lon, maxDistanceKm)` принимает корректные координаты и радиус
0–200 км. Пространственные ячейки консервативно выбирают пакеты, затем Haversine
проверяет точную дистанцию до городов. Равные расстояния разрешаются меньшим ID.
Границы ячеек, полюса и переход через 180° учитываются. `success(null)` означает,
что в проверенных данных нет города в радиусе; недоступные данные возвращают
`DataFailure`, а не ложное отсутствие. Это **подсказка названия**, а не определение
административной принадлежности или timezone GPS-точки. GPS orchestration,
региональные границы и coordinate-to-timezone resolver сюда не входят.

## Версии и офлайн

Индекс и базовый обзор включены в precache: после успешной установки они доступны
без сети. Пакеты исключены из precache. Workbox маршрутизирует их через NetworkOnly;
после проверки размера, SHA-256, schema, версии, ID и пространственного соответствия
слой хранения сохраняет пакет в IndexedDB. Непроверенный ответ не кешируется.
Уже скачанные пакеты читаются из IndexedDB, включая после перезапуска приложения.
Обычные ограничения хранения браузера (очистка сайта, вытеснение) сохраняются.

База `salah-city-catalog`, версия 1, содержит публичные пакеты и текущий/предыдущий
индекс. База `salah` с пользовательским выбором и расписаниями не мигрирует и не
очищается. История recent cities не вводится. Рабочая версия фиксирована на время
жизни Worker; URL и ключи пакетов включают версию. Некорректное обновление индекса
оставляет прежний; если новый пакет недоступен, поиск и nearest могут использовать
**целиком** предыдущий индекс с его локальными пакетами. Поиск сообщает об этом
через `previousVersion`. Пакеты разных версий не объединяются. Старые локальные
пакеты сохраняются; сброс данных сайта удаляет обе базы.

Service worker при активации удаляет только прежний runtime-кеш `city-data` с
монолитом. Сохранённое место содержит достаточно данных для расчёта независимо
от каталога; согласованность расписания определяется его контекстом.

## Воспроизведение и бюджеты

Для перепаковки проверенных committed-данных без сети:

```sh
npm run data:update:cities -- --repack
```

Для повторного импорта нужны **те же** три исходных архива/файла из
`scripts/geonames-sources.json` в локальном каталоге:

```sh
GEONAMES_INPUT_DIR=/path/to/snapshot npm run data:update:cities
```

Генератор проверяет все SHA-256 до импорта и полностью проверяет новые файлы до
публикации индекса. GeoNames обновляет URL ежедневно: свежий файл с другим хешем
будет отклонён. Архив исходных снимков нужно сохранять отдельно; текущий ежедневный
URL не гарантирует повторное получение старого снимка. При намеренном обновлении
следует проверить новые снимки, обновить pins и notices, повторить генерацию и QA.
Новый набор сохраняет идентичность и координаты прежней выборки; расширение выборки
не является частью этого изменения. Версия — первые 20 hex SHA-256 содержимого,
метаданных источника и параметров упаковки. Повторная генерация побайтово стабильна.

`build:check` проверяет индекс, все обязательные пакеты, SHA-256, маршрутизацию
поиска, пространственное покрытие и совпадение обзора с пакетами. Отсутствующий,
лишний, повреждённый или несовместимый пакет и старый монолит приводят к ошибке.
Остальные лимиты не увеличены.

| Артефакт | Бюджет, байт | Измерено, байт |
| --- | ---: | ---: |
| Индекс с базовым обзором | 655 360 | 646 202 |
| Каждый пакет | 131 072 | максимум 71 042 |

JS-размеры актуализированы по итоговой production-сборке 7 сентября 2026 года;
полные результаты — в [матрице проверки](audit-verification.md).

Суммарные данные выросли относительно монолита из-за явных регионов, отдельных
поисковых имён и индекса. Они больше не являются одной обязательной загрузкой.

## Browser-измерения

Production Vite preview, `http://127.0.0.1:4175/salah-pwa/`, чистый Chromium,
включённый service worker. Считаются уникальные URL данных и размеры исходных JSON,
без HTTP-заголовков и транспортного сжатия. Playwright может показывать два события
для одного URL: запрос Worker к service worker и сетевой запрос самого service
worker; это не две независимые загрузки файла.

| Сценарий | До | После |
| --- | --- | --- |
| Первый главный экран/установка | Нет городских данных | Только индекс 646 202 байт; 0 пакетов |
| Первый экран выбора места | 0 городских запросов | 0 пакетов |
| Открытие поиска/обзора | Монолит 7 746 467 байт | Только индекс (из precache после установки), 0 пакетов |
| Поиск «Киров» | Тот же монолит | 15 пакетов, 657 590 байт; 2 Кирова различимы |
| Полный каталог обязателен для сохранённого места | Нет | Нет |

Индекс на 91,7% меньше прежней обязательной загрузки поиска. Цена базовой офлайн-
доступности — дополнительные 646 202 байта при установке. Точные запросы поиска,
офлайн-поведение загруженных/незагруженных пакетов и очистка старого кеша закреплены
в `tests/city-catalog.spec.ts`; PWA проверяется на свежей production-сборке.


Визуальная проверка выполнена на 1440×900 и 390×844: видны названия регионов,
соблюдается общий порядок совпадений, горизонтального переполнения нет. Страница
имеет ожидаемые URL/title, содержимое не пустое, framework overlay и ошибки
консоли отсутствуют. Нативное окружение Browser plugin недоступно; использован
Playwright проекта. Оба размера подтвердили один сетевой запрос индекса при
установке и получение индекса из service worker при открытии обзора.


Проверки первоначальной поставки каталога: 327 Vitest-тестов, lint, typecheck, production build,
`build:check`, 7 offline smoke-сценариев, SW update smoke, 3 CSP-сценария,
26 UI-сценариев Chromium, 6 privacy-сценариев и 10 cross-browser сценариев
(Firefox, WebKit, mobile Safari portrait/landscape) прошли. Две проверки ориентации
штатно пропущены для desktop-профилей; в обоих mobile-профилях выполнены.
Зависимости не менялись; лицензии наборов данных проверены по первичному источнику.
