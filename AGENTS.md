# AGENTS.md

## Область действия

Эти инструкции применяются ко всему репозиторию. Если в подкаталоге появится свой `AGENTS.md`, он уточняет правила для этой части проекта.

## Стек и ограничения

- Используй React 19, TypeScript в строгом режиме и Vite.
- Для IndexedDB используй `idb`; не обращайся к базе напрямую из UI-компонентов.
- PWA реализуй через `vite-plugin-pwa` и Workbox.
- Локальное состояние храни в React state и пользовательских hooks.
- Не добавляй роутер, глобальный state manager, UI-kit или другие крупные зависимости без подтверждённой необходимости.
- Следуй DRY, KISS и YAGNI. Предпочитай небольшие, явные и легко удаляемые решения.

## Архитектура

- Отделяй UI от IndexedDB небольшим типизированным слоем хранения.
- Выноси бизнес-правила, преобразования и вычисления в чистые функции.
- Оформляй каждое изменение схемы IndexedDB явной, последовательной миграцией.
- Держи компоненты сфокусированными; общую логику извлекай только при реальном повторном использовании.
- Сначала изучай существующие паттерны проекта и сохраняй их, если они остаются корректными.
- Комментируй по-русски только неочевидные инварианты, причины решений и сложные алгоритмы.

## Разработка через тесты

- Для нового поведения сначала добавляй или изменяй тест, наблюдай ожидаемое падение, затем реализуй минимальное решение и выполняй рефакторинг.
- Используй Vitest для чистых функций и модулей, React Testing Library с `user-event` для пользовательских сценариев, `jsdom` для DOM и `fake-indexeddb` для слоя хранения.
- Проверяй публичное поведение, а не внутреннее устройство компонентов.
- Для исправления дефекта добавляй регрессионный тест.
- Не ослабляй типизацию и не удаляй полезные проверки ради прохождения тестов.

## Интерфейс

- Сохраняй визуальный язык рукописного дневника: бумажная фактура, спокойные чернильные цвета и умеренная декоративность без ущерба читаемости.
- Поддерживай светлую и тёмную темы через системные настройки.
- Проектируй mobile-first адаптивный интерфейс с учётом `safe-area-inset-*`.
- Обеспечивай полноценное управление клавиатурой и сенсорный ввод.
- Интерактивные цели должны быть не меньше 44×44 px.
- Уважай `prefers-reduced-motion`; движение не должно быть обязательным для понимания состояния.

## PWA и офлайн-режим

- Поддерживай корректный manifest и устанавливаемость приложения.
- Service worker должен обновляться автоматически и не оставлять интерфейс в несовместимом состоянии.
- После первого успешного запуска основные пользовательские сценарии должны работать без сети.
- Явно разделяй precache ресурсов приложения и runtime-кеширование данных; не кешируй чувствительные или непредсказуемые ответы без причины.
- Изменения PWA проверяй production-сборкой и offline smoke-test, а не только dev-сервером.

## Проверка и доставка

- Перед завершением изменения запускай релевантные тесты, затем полный набор тестов, typecheck и production build в объёме, соразмерном изменению.
- Перед релизом обязательны: воспроизводимая установка зависимостей, все тесты, typecheck, production build и offline smoke-test.
- GitHub Actions должен устанавливать зависимости из lock-файла, выполнять проверки и публиковать содержимое `dist` в GitHub Pages.
- Не скрывай ошибки CI, TypeScript, сборки или линтера отключением правил без документированной причины.

## Работа с репозиторием

- Сохраняй пользовательские и несвязанные изменения; не выполняй массовое форматирование без необходимости.
- Делай минимальные сфокусированные изменения и не создавай преждевременные абстракции.
- Не коммить, не отправляй изменения и не переписывай историю Git без прямого запроса пользователя.
