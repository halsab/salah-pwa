# Salah

Salah — автономное PWA времени намаза для выбранного места на React 19,
TypeScript и Vite. Источник подбирается автоматически: поддерживаемая официальная
таблица, региональный расчётный профиль или общий расчёт на устройстве.
Выбирать метод при первом запуске не обязательно. Начальный пример — Казань;
город или GPS можно выбрать самостоятельно.

Salah — информационное приложение и не представляет ДУМ РТ или другую религиозную организацию.
Расчётное время может отличаться от расписания местной мечети.
При наличии официального местного расписания рекомендуется руководствоваться им.

## Источник времени и настройки

В automatic приложение использует официальную таблицу при подтверждённом
покрытии места и даты. Сейчас поставщик один —
[ДУМ Республики Татарстан](https://dumrt.ru/ru/help-info/prayertime/):
44 опубликованных пункта, полный 2026 год. Для GPS внутри подтверждённой
границы Татарстана выбирается ближайший пункт таблицы; координаты GPS
не подменяются координатами этого пункта. Без официального покрытия работает
расчёт `adhan`, включая правила высоких широт. Название расчётного профиля
не делает результат официальным расписанием.

Сетевой сбой не меняет известный официальный источник на расчёт: остаётся
сохранённая таблица либо явное сообщение о недоступных данных. За пределами
опубликованного года automatic использует расчёт, а manual official сообщает
об отсутствии покрытия. Поздний сухур относится к вечеру накануне дня поста:
для строки 5 мая время `23:54` наступает 4 мая. Календарная дата показана рядом
с отметкой и в сведениях об источнике; см. [хронологию](docs/prayer-chronology.md).

Главный экран выделяет следующий намаз или ближайший джамаат. Нажатие на
название источника под расписанием открывает пункт таблицы, её актуальность
либо эффективные параметры расчёта. Базовые настройки содержат место, тему,
режим времени и данные. Путь к экспертным параметрам:
«Настройки → Время намаза → Расширенные настройки». Применение расчёта включает
manual. Возврат к automatic одним действием сохраняет черновик параметров,
но прекращает применять его к автоматическому расписанию.

## Место и работа без сети

GPS обрабатывается локально: два одноразовых измерения дают быстрый результат
и уточняют его при существенном улучшении. Непрерывного отслеживания нет.
Сохранённый ручной город не запускает GPS; устаревшее автоматическое место
обновляется только при уже выданном разрешении. Поиск названия рядом использует
только имеющиеся на устройстве пакеты и не отправляет координаты геокодеру.

Город содержит свою IANA timezone. Для GPS автоматическая зона по локальной
границе поддержана только в Татарстане. За его пределами используется явно
обозначенная зона устройства, которую можно изменить в сведениях о месте.
Расчёт следует зоне места; опубликованная таблица ДУМ РТ всегда использует
`Europe/Moscow`. Границы, погрешность и ограничения описаны в
[локальной географии](docs/local-geography.md).

Базовый обзор содержит до трёх крупнейших городов каждой страны. Поиск загружает
подходящие пакеты GeoNames; затем они доступны без сети. Всего в поставке
69 037 городов с населением от 5 000, но **весь мировой каталог не загружается
при установке**. Отсутствующие пакеты и неполные результаты обозначаются явно.
Сохранённого места достаточно для автономного расчёта даже без каталога.
[Формат, ранжирование, генерация и бюджеты](docs/city-catalog.md).

При повторном запуске локальные настройки и проверенный набор расписаний
читаются до обращения к сети. Фоновая проверка manifest загружает изменённый
набор и атомарно заменяет его только после проверки целостности и полноты.
Первое получение официальной таблицы требует сети; при недоступности таблицы
в уже открытом приложении можно использовать расчёт для доступного места. Оболочка, геограница, обзор
и статическая страница конфиденциальности доступны офлайн после успешной
установки service worker. Браузер может очистить или вытеснить данные.

«Настройки → Данные → Сбросить данные приложения» после подтверждения удаляет
место, координаты, timezone, настройки, оформление и сохранённые таблицы во всех
вкладках этого браузера. Старые async-ответы не восстанавливают их. Оболочка,
загруженные публичные справочники и защитные служебные отметки остаются; для полной
очистки используются настройки сайта в браузере. Разрешение GPS управляется
отдельно. После сброса место выбирается заново, фоновый GPS сам не запускается.
[Хранение, сетевые потоки и граница сброса](docs/app-data.md).

## Локальный запуск и данные

Используйте Node 24 из `.nvmrc` (например, `nvm install && nvm use`):

```sh
npm ci
npm run dev
```

Подготовленный dataset уже включён в `public/data`; скачивать исходные таблицы
для запуска или production-сборки не нужно. Production preview после сборки:
`npm run preview -- --host 127.0.0.1 --port 4175`, адрес
[localhost](http://127.0.0.1:4175/salah-pwa/).

Команды подготовки данных:

```sh
npm run data:update                            # сеть: CSV всех пунктов ДУМ РТ
npm run data:update:prayer-manifest            # локально: manifest и coverage текущего JSON
npm run data:update:cities -- --repack         # локально: перепаковка committed-каталога
npm run data:build:geography                   # локально: геопакет из закреплённого снимка
npm run data:check:geography                   # проверка без изменения артефакта
```

`data:update` проверяет полноту текущего года и добавляет следующий только
при наличии всех строк для всех пунктов; `PRAYER_DATA_YEAR=2026` задаёт конкретный
год. Значения таблиц не заменяются расчётом. Диагностика спорных значений выводится
до записи. Manifest хранит SHA-256 и возрастающий `sequence`; проверка hash
подтверждает целостность, а не подпись поставщика. Для повторного импорта городов:
`GEONAMES_INPUT_DIR=/path/to/snapshot npm run data:update:cities`; нужны исходные
снимки с хешами из `scripts/geonames-sources.json`, а не произвольный свежий дамп.

## Проверки

После `npm ci`, на Node из `.nvmrc`:

```sh
npm run actions:check
npm run lint
npm test
npm run test:coverage
npm run typecheck
npm run build
npm run build:check
npm run security:audit
npm run license:check
npx playwright install --with-deps chromium firefox webkit
npm run security:csp
npm run smoke:offline
npm run test:e2e
npm run smoke:sw-update
```

Playwright сам запускает production preview на `127.0.0.1:4175`. Освободите этот
порт от старого сервера. Browser suites запускаются после свежей сборки;
`smoke:sw-update` — отдельно от остальных: он временно меняет `dist/sw.js`,
проверяет единственную перезагрузку и восстанавливает исходные байты в `finally`.
Успешная локальная проверка не означает успешный удалённый CI.

## Архитектура и публикация

UI использует React state и небольшие hooks без роутера, глобального state manager
и UI-kit. Чистые доменные функции отвечают за resolver, события, дату и географию.
Типизированный слой `idb` изолирует IndexedDB, явные миграции доведены до v9.
Workbox precache хранит оболочку и базовые публичные данные; таблицы и пакеты
городов проходят NetworkOnly и сохраняются прикладным слоем после валидации.
Runtime Nominatim, аналитики, рекламы, аккаунтов и собственного backend нет.
GitHub Pages получает обычные HTTP-запросы и их сетевые метаданные; приложение
не добавляет в них GPS или настройки. Состав пакетов может косвенно указывать
на область поиска. [Контракты resolver и обновлений](docs/prayer-sources.md).

Push в `main`, pull request и ручной запуск проверочного workflow выполняют
проверки без публикации. Workflow `Обновление расписания ДУМ РТ` еженедельно
создаёт PR с изменёнными данными; для этого GitHub Actions должно быть разрешено
создание PR. Он не публикует приложение.

Релиз запускается вручную workflow `Создать релиз` только из `main`. Он фиксирует
commit, вычисляет следующий `vYY.N`, вызывает все проверки с `deploy: true`,
публикует содержимое `dist` через GitHub Pages, затем создаёт Git-тег и GitHub Release.
В новом году нумерация начинается с 1. Одновременно выполняется один релиз;
источник Pages в настройках репозитория — **GitHub Actions**.
